## 修复：切换前台窗口时整屏闪（原生任务栏可见性互抢）

**现象**：Alt+Z（用户自定的切换键）切软件时整屏白/黑闪一下；不依赖具体应用。

**根因（日志证据，`%LOCALAPPDATA%\com.seelen.seelen-ui\logs\SLU Service.log`）**：

- 每次前台变化，explorer 都把 `Shell_TrayWnd` 重新显示一次，Seelen 再 `SW_HIDE` 回去。
- 同一秒出现多次：16:40:00 有 4 次，16:33:00 / 16:39:43 各 3 次，切换瞬间（17:06:54–55）2 次。
- 机制：被 `SW_HIDE` 的任务栏让 explorer 认为"没显示"，于是下一次 shell 事件（前台变化、auto-hide 探头）就再 show
  一次；每次 show/hide 都重新合成一条全宽 topmost 窗口 → 整屏闪。
- 排除项：`@seelen/task-switcher` 与 `@seelen/window-manager` 都是 disabled，所以 task switcher / WM z-order
  不是元凶；壁纸 pause 只影响播放器不影响窗口。

**修法（commit 452ddfae，分支见 git log）**：

- `src/service/windows_api/mod.rs` 新增 `set_window_cloaked` / `suppress_window_visuals` /
  `restore_window_visuals`：空窗口区域（不绘制、不接收点击）+ DWM `DWMWA_CLOAK`（不参与合成），**不改可见性**，explorer
  没有"需要恢复"的状态。
- `src/service/shutdown.rs`：hide pass 与 250ms 巡逻统一走 `suppress_taskbars()`，按 hwnd
  去重（`SUPPRESSED_TASKBARS`），不再反复 `SW_HIDE`；`restore_native_taskbar` 先清区域/解 cloak 再显示。cloak
  失败则回落旧 SW_HIDE 行为。
- 顺带修了 lefthook 卡住的 `hidden.svelte.ts` 格式问题（仅格式化）。

**验证状态**：`cargo check --bin slu-service` 通过、`cargo fmt --check` 干净。非提权 PowerShell 实测
`DwmSetWindowAttribute(DWMWA_CLOAK)` 返回 `0x80070005`（等于 explorer 同权限被拒），`SetWindowRgn`
可成功；服务的计划任务 `Seelen UI Service` 是 `RunLevel=Highest`，理论可用。 **待观察**：出包后看日志应由
`Hiding visible native taskbar` 变成 `Suppressed native taskbar`；若出现 `Failed to suppress native taskbar` 说明 cloak
被拒，需要换方案（移出屏幕 / 其它手段）。

**注意**：`@seelen/task-switcher` 默认关闭，用户没有自定义快捷键（`settings_shortcuts.json` 里 shortcuts 为空），Alt+Z
来自外部工具。

## dock 呼不出（根因 + 自愈补丁）

- 现象：底边鼠标贴到底，dock 不出来；重启 Seelen 后恢复。
- 证据（Seelen UI.log）：11:19 出现多 widget `Liveness prove failed`（wallpaper/toolbar/apps-menu/weg，weg 到 attempt
  5/5 被 reload），同时 `TracedMutex` 等锁 5.2s（widget deployments，thread #457），weg 报
  `IPC custom protocol failed → postMessage`。
- 机制：WEG 重载后 JS 活着（liveness ping 有回应，所以不会再被 reload），但 `GlobalMouseMove` 不再送达 → `mousePos` 冻结
  → `isMouseOverEdge` 恒 false → `_hiddenByAutohide` 恒 true。属于“存活探测通过但功能已死”。
- 补丁：`weg/state/getters.svelte.ts` 新增 `refreshMousePos()`；`weg/state/hidden.svelte.ts` 在 `_hiddenByAutohide` 为
  true 时每 300ms 通过 IPC 重读光标位置（顺带修复 init 失败导致 LazyRune 未初始化的崩溃）。
- 临时恢复手段：`slu.exe restart`。

## widget 锁竞争（C + A，上游隐患）

- 现象：11:19 一次性 reload 了 5 个 widget，WEG 重载后 dock 呼不出。
- 根因（git blame 全是 eythaann，b5bc93ac9 / 17bf226e5）：`WidgetManager::reconcile` 在 `deployments.for_each` 闭包里调
  `start_all_webviews()`，即**持全局 deployments 锁创建 WebView2**（每个几百 ms，累计 5s+）；`suspend_all`/`retain`
  同样在锁内销毁 webview。liveness 等待超时只有 3s → 全体判死 → 批量 swift_restart。
- C（47411535）：`TracedMutex::is_locked()` + `SyncHashMap::is_locked()` 非阻塞探测；liveness 在 ping
  前和超时后各检查一次，锁被占就 `continue`，不计失败。
- A（2f013b5c）：`deployments` 值改 `Arc<WidgetDeployment>`；reconcile 先快照（按 wall→toolbar→weg 排序），锁外创建
  webview（顺带消除了原来“优先级三个 widget 被处理两次”的冗余）；`suspend_all` 与陈旧资源清理都在锁外析构。
- 临时恢复手段仍是 `slu.exe restart`。
- 注意：直连 GitHub 已不通，git push 需要 `-c http.proxy=http://127.0.0.1:45097`（系统代理端口随客户端重启变化）。
